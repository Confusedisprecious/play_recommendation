## 社交与公开资讯

- SearXNG：用于发现公开网页结果。站点脚本只接入自托管或明确授权的实例，
  并用域名白名单控制候选来源。
- RSSHub：用于订阅可公开访问的 RSS/Atom 路由。路由由维护者在
  `data/source_registry.json` 中显式配置。
- Bing News RSS：作为无需账号的增量层，只自动发布武汉市政府、长江网、湖北广电、
  荆楚网等白名单域名在 45 天内的公开资讯。每次更新会合并仍在有效期内的历史结果，
  避免搜索结果波动导致内容倒退。
- FreshRSS：适合作为人工审核工作台，不作为网页运行时依赖。
- MediaCrawler：虽然覆盖小红书、抖音、微博等平台，但依赖登录状态和浏览器自动化，
  且项目说明限制商业和大规模抓取，因此不接入本项目的生产采集链路。

发现结果只写入 `data/social_candidates.json`，状态为 `pending`。只有人工核验过标题、
摘要、日期、地点和公开链接后，才可加入 `data/social_sources.json`，再由
`scripts/social_ingest.py` 生成页面使用的 `data/social_feed.json`。

白名单新闻 RSS 是例外：候选状态为 `auto_trusted`，可由 `social_ingest.py` 自动合并。
页面分别展示内容发布时间、抓取时间和时效标签；超过 30 天的社交内容明确显示为
“历史参考”，不会用新的抓取时间冒充新内容。

## 图片与视频

- 景区照片来自 Wikimedia Commons 的开放许可文件，运行
  `scripts/fetch_commons_media.py` 会下载缩略图并生成包含作者、许可和来源链接的
  `data/media_gallery.json`。
- 社交视频不下载、不转存，页面使用关联景区照片作为封面并链接到原公开页面。
- 票价、开放时间和活动档期属于易变化信息，页面必须保留“出行前核实”提示。

## 2026-10 更新：B站视频流与公众号方案

### B站视频（已接入定时更新）

CI（`.github/workflows/update.yml`）会在每次定时更新时用 Docker 启动
`diygod/rsshub-chromium-bundled`（内置无头浏览器），并通过
`RSSHUB_BASE_URL=http://127.0.0.1:1200` 提供给数据脚本。

`data/source_registry.json` 的 `feeds.routes` 目前订阅三个关键词（武汉遛娃 /
武汉亲子 / 武汉溜娃），走 RSSHub 的 `/bilibili/vsearch/:kw/pubdate/no` 路由，
按"最新发布"取视频。抓到的条目进入 `social_candidates.json`，状态 `pending`。

人工核验后发布（本地运行）：

```bash
python scripts/review_candidates.py --list                 # 看待核验清单
python scripts/review_candidates.py --approve --days 14    # 核验最近14天全部
python scripts/review_candidates.py --approve --keyword 遛娃 --days 7
```

核验即写入 `reviewed` 并立刻重建 `social_feed.json`，页面下一轮加载即可见。
页面端只展示最近 14 天内的内容，过期自动消失（见 `js/data-service-v2.js` 的
`MAX_FEED_AGE_DAYS`）。

若要新增可信官方账号（如微博政务号），在 `feeds.routes` 里用对象写法并标记
`trusted: true`，条目会直接以 `auto_trusted`（官方来源）身份进入信息流：

```json
{ "path": "/weibo/user/<uid>", "platform": "weibo", "trusted": true, "label": "武汉发布" }
```

微博路由在 RSSHub 侧通常需要配置 `WEIBO_COOKIE` 环境变量，且 uid 需人工核实
归属后再标记 trusted。

### 微信公众号（江夏发现 / 武汉文旅等）

推荐 [wewe-rss](https://github.com/cooderl/wewe-rss)（基于微信读书，v2.x 接口
稳定）：本地或国内小服务器部署，用微信扫码登录一次，即可把任意公众号转成 RSS，
配合 `scripts/import_social_exports.py` 走既有的"授权导出 + 人工核验"流程。
该方案需要登录态，按项目合规策略仅作为本地授权导入工具，不进入 CI 采集链路。
